# M2: structured extraction and dry runs

This increment connects the existing backend to Gemini and records a decision
without executing it. It uses the direct Google GenAI SDK; no ADK runtime,
cloud deployment, or additional database is required.

Latest validation: Flash-Lite passed all 20 development cases, and the optional
availability fallback passed the 69-test local regression suite. Analysis stays
read-only; [separate reviewed execution](reviewed-execution.md) is now available.

## Configuration

Put actual keys only in `.env`, which Git ignores. `.env.example` documents the
setting names with empty key values and can be committed. Process environment
variables override `.env`.

```dotenv
GEMINI_API_KEY=your_key_here
GEMINI_MODEL=gemini-3.8-flash
# Optional, for analyze only:
GEMINI_FALLBACK_MODEL=gemini-3.5-flash-lite
```

Do not send credentials in request text. The Gemini adapter blocks configured
keys and common credential formats before sending or saving M2 text. This is
not a general sensitive-data detector. Use synthetic data only, particularly
with the free API tier. No billing settings are changed by this application.

## Run from Git Bash

```bash
# Inspect the M1 payment IDs available in your local database:
.venv/Scripts/python.exe -m payresolve m1 list-payments
.venv/Scripts/python.exe -m payresolve m2 analyze --message 'Refund USD 5 from pi_YOUR_PAYMENT_ID'
# Or analyze an intake request already stored by POST /requests:
.venv/Scripts/python.exe -m payresolve m2 analyze --request-id YOUR_REQUEST_UUID
# This command is local and makes no API requests:
.venv/Scripts/python.exe -m payresolve m2 show YOUR_ANALYSIS_UUID
```

Each analysis has its own UUID, model/prompt version, validated extraction,
decision, token usage, HTTP attempt count, latency, and creation time. Failures store fixed error
codes/messages. The SQLite `analysis_runs` table is additive; intake requests
remain `received`. An interrupted process can leave an analysis `started`;
running analysis again creates a new record and never executes a refund.

Decisions are `propose_refund`, `clarify`, `reject`, or `no_action`. Every decision
has `dry_run=true` and `executed=false`. Missing/ambiguous targets, missing amount
or currency, and unsupported numeric forms require clarification. Only a single
literal PaymentIntent ID present in the message may be selected; order-number
mapping and conversational clarification are not implemented.

The policy requires a locally managed M1 sandbox payment, no unresolved refund,
matching sandbox identity, successful capture, no dispute, USD currency, and a
positive amount no greater than the freshly retrieved refundable balance.
Amounts use exact decimal conversion to cents; the numeric evidence must occur
in the message. A full refund requires explicit full-refund extraction. Words,
cents, percentage calculations, and ambiguous amounts are deliberately deferred.

The model has no tools, Stripe credentials, or database access. It sees only the
synthetic request and extraction instructions/schema. Pydantic validates its
output; schema validity alone does not guarantee correct interpretation. A
proposal is a snapshot, not authorization: future execution must revalidate
state and use M1's durable idempotency workflow. Do not convert a proposal
directly into an unchecked Stripe call.

## Evaluation and verification

`evals/refund_intents.json` contains 20 labeled synthetic cases. The separate
live evaluator sends only each message to Gemini and applies the same policy
against fixed synthetic payments. It never calls Stripe. Expected labels stay
outside the prompt. Reports include per-case outputs, errors, usage/latency,
model/prompt version, dataset hash, and exact expected-field scores under the
ignored `instance/evals/` directory. Unattempted/provider-error cases cannot
inflate the requested-case pass rate. This small development set is not the
proposal's independent 100–150 case benchmark or an estimate of production quality.

```bash
# Start small. Expand only after the first two work:
.venv/Scripts/python.exe -m payresolve m2 eval --limit 2
.venv/Scripts/python.exe -m payresolve m2 eval --limit 20
```

Calls are spaced six seconds apart by default. Rate limits depend on the
project. Provider errors stop the run, leaving a report marked `incomplete`.
The extractor allows at most three HTTP attempts for transient server errors
(500, 502, 503, 504). Backoff is 2 then 4 seconds plus
up to 0.5 seconds of jitter; a server `Retry-After` header can override the delay.
Each request has a 30-second transport timeout. There is only one retry layer,
inside the SDK. Authentication, invalid requests, quota errors (429), incomplete
responses, and invalid structured output are not retried. Attempt counts and
total latency including retries are recorded on success and failure; token usage
is the successful response's reported usage, not an estimate for failed attempts.
When `GEMINI_FALLBACK_MODEL` is nonempty and different from `GEMINI_MODEL`,
`analyze` tries it only after a server/connection availability error. Quota,
authentication, invalid request, incomplete response, and invalid extraction
errors never trigger fallback. Each model has its own three-attempt limit
(at most six HTTP attempts across both). Successful results retain the actual
`model`, `requested_model`, `fallback_used`, and per-model `attempt_history`.
Both-model failures persist that history too. Evaluations always ignore the
fallback setting, keeping each model's scores independent. There is no caching.
CLI exits 1 for
failed/incomplete analyses or unsuccessful evaluations; a completed clarification
or rejection exits 0 because analysis itself completed.

for exactly three HTTP attempts on Interactions, verified at the transport
boundary. Recheck this behavior before upgrading the SDK or changing endpoints.

## API references

- [Structured output](https://ai.google.dev/gemini-api/docs/structured-output):
  JSON schema plus local validation.
- [Interactions](https://ai.google.dev/gemini-api/docs/interactions): one
  stateless request with `store=false` and no tools or automatic continuation.
  Disabling interaction storage does not override the provider's general data terms.
- [Gemini pricing](https://ai.google.dev/gemini-api/docs/pricing): free-tier limits
  and data-use terms; eligibility depends on the configured project/model.
